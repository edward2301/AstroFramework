# 项目上手指南

面向刚接手这个项目的开发者。读完这一份，应该能独立改页面、加内容、定位问题。

更细的设计取舍与约束条文见 [`开发框架设计.md`](开发框架设计.md)；本文只讲「是什么、怎么跑、改哪里」。

---

## 1. 这个项目是什么

一个 **B2B 工业品出口站**，Astro 静态构建，没有运行期服务端。

- 英文站是主站，路径在根目录：`/products/a1/`
- 中文站是同一份内容与结构的语言层副本，路径带 `/zh` 前缀：`/zh/products/a1/`（404 每种语言各一份，语言与页面一致）
- 内容以文件形式与代码同仓；发布用 `npm run deploy`（构建后经 Wrangler 上传到 Cloudflare Pages）

构建产物是纯静态的 HTML、CSS、图片，部署到 **Cloudflare Pages**；交互数据另存 **Cloudflare D1**，
由运维用 Wrangler CLI 保存与读写，页面代码不连库。

## 2. 五分钟跑起来

### 2.1 环境

Node 版本以 `.nvmrc` 为准（`package.json` 的 `engines` 同时约束 node 与 npm）。先 `nvm use`（或 fnm/volta）切到 `.nvmrc` 的版本；版本不对时 `npm run build` 会报 `Node.js vXX is not supported by Astro`，那是环境问题，不是代码问题。

### 2.2 命令

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `npm run dev` | 开发服务器，默认 http://localhost:4321 | 日常改页面 |
| `npm run validate` | 内容体检，不构建 | 提交前自查 |
| `npm run check` | TypeScript 与 Astro 类型检查 | 改完组件想知道有没有接错参数 |
| `npm run test` | Vitest 单测（清单见 `tests/`） | 改 `lib/utils`、`i18n/routing`、`seo/*`、`lib/nav` 等模块后 |
| `npm run check-links` | 检查 `dist/` 里的站内链接与语言版本配对 | 想单独验证链接 |
| `npm run build` | **类型检查 → 内容体检 → 构建 → 链接检查** | 发布前 |
| `npm run preview` | 预览构建产物 | 看真实产物效果 |
| `npm run deploy` | 构建并把 `dist/` 部署到 Cloudflare Pages（构建已含分语言 404 复制与型号旧路径 301 生成） | 发布 |

`build` 是一条串起来的流水线，任何一道不过就停，**不存在绕过校验的构建入口**；
它还会按 `LOCALES` 复制分语言 404 产物，产出的 `dist/` 可直接上传。
若改用 Cloudflare Pages 的 Git 集成自动构建，构建命令同为 `npm run build`、产物目录 `dist/`，
跑的是同一条流水线。质量门 = `npm run validate && npm run check && npm run test`。

### 2.3 页面在哪

启动后直接访问：

| 地址 | 页面 |
|---|---|
| `/` `/zh/` | 首页 |
| `/products/` `/zh/products/` | 产品总览（全型号目录 + 品类筛选/搜索） |
| `/products/category-a/` | 品类页（参数对比表与采购信息在这） |
| `/products/a1/` | 型号页（规格表在这；旧三层路径 301 到这里） |
| `/contact/quote/` | 询价页（主导航不设此项：页眉 CTA「获取报价」即入口，同一 URL 不重复占位） |
| 任意不存在的路径 | `dist/404.html`（英文）；`/zh/` 下的无效路径落到 `dist/zh/404.html`，由 Cloudflare Pages 按前缀就近查找（构建守卫从 `dist/zh/404/index.html` 复制） |

导航里的全部栏目都能打开。应用方向、案例、指南、问答有列表页与详情路由（录入内容即自动产出页面）；资料下载由 `static.ts` 的 `sectionContent()` 读 `downloads` 集合渲染列表，列表项直达 `file` 字段。

## 3. 一次访问是怎么变成页面的

Astro 静态构建：所有页面在 **构建时** 就渲染成 HTML，用户访问时不执行任何服务端逻辑。

以型号页 `/products/a1/` 为例：

```
1. 构建开始
2. scripts/build-guard.mjs 的 astro:build:start 钩子
   └─ 跑 scripts/validate-content.mjs → 内容不合规直接中断
3. 单路由分发器 src/pages/[...slug].astro 执行 getStaticPaths()
   └─ 遍历 LOCALES × (页面条目 + 各内容集合)，生成全部路径
4. 分发器把路径参数交给载荷装配：
   ├─ 静态页 → src/lib/pages/static.ts 按版式装配（文案来自 src/data/pages/entries/）
   └─ 内容页 → src/lib/pages/render.ts 按集合装配：
      ├─ src/lib/content/models.ts    取型号详情（含替代型号、关联应用/案例）
      ├─ src/lib/content/localize.ts  按语言选中文或英文字段
      ├─ src/lib/seo/meta.ts          补品牌后缀（src/lib/seo/branding.ts 单点实现）+ 校验长度
      ├─ src/lib/seo/breadcrumb.ts    生成面包屑（中英文标签不同）
      └─ src/lib/seo/schema.ts        生成 Product 与 BreadcrumbList 结构化数据
5. src/layouts/BaseLayout.astro 套外壳
   ├─ 取导航：src/lib/content/site.ts 只取品类/应用方向的子项，
   │  主导航与页脚由 src/lib/nav.ts 从页面条目的 nav 字段派生
   ├─ 输出 <head>：title / description / canonical / hreflang / og / JSON-LD
   └─ 渲染 Header、<slot>、Footer
6. src/components/pages/ModelBody.astro 渲染正文
7. 产物写入 dist/products/a1/index.html
8. astro:build:done 钩子 → 扫描全站站内链接，断链即失败
```

**关键理解：** 页面里没有「请求时」的逻辑。`getStaticPaths` 决定了会生成哪些页面，没有列进去的路径永远不会存在——所以不存在的型号自然是 404，不需要专门处理。

## 4. 分层与模块职责

只看三条硬规则；完整目录树、模块表与依赖方向见 `docs/开发框架设计.md` §1–§3 与 `.codebuddy/rules/architecture.md`。

1. **页面不直接调 `getCollection`**，一律经 `src/lib/content`。换数据源时只改这一层。
2. **组件不取数**，数据由 props 传入。
3. **页面不手写 `<title>` / `<meta>` / JSON-LD**，全部经 `BaseLayout` → `SEO` / `JsonLd`。

## 5. 中英文两个版本怎么工作

### 5.1 路由结构

默认语言（英文）不带前缀，中文带 `/zh`：

```
/products/a1/       英文
/zh/products/a1/    中文
```

**内容 slug 两种语言共用**（如 `category-a`、`a1`）。翻译 slug 会变成两套 URL 体系，收益只有美观，代价是重定向表和一致性校验。型号 id 是 `/products/` 下的全局路径段，不得与品类 id 相同；旧三层路径由构建期生成 301。

### 5.2 四层文案，各有归属

| 层 | 存在哪里 | 例子 |
|---|---|---|
| **通用界面文案** | `src/i18n/ui.ts` | 按钮「获取报价」、表格列头「最小起订量」、面包屑「首页」、页眉 CTA、部分页面 h1 |
| **页面条目** | `src/data/pages/entries/*.ts` | 主导航/页脚标签（`nav.main.label` / `nav.footer.label`）、`heading`、栏目正文、页面级 `seo` |
| **内容** | 各参数型条目的 `locales.zh` | 品类名、型号名、规格表、采购信息 |
| **内容页 SEO** | 内容条目的 `seoTitle` / `locales.zh.seoTitle` | 型号页、品类页、文章页的标题与描述 |

为什么要分开：界面文案是**代码**，随代码一同维护；内容是**数据**，由运营维护。混在一起后，运营改一句话要找开发。

### 5.3 译文：语言块必填，必填字段不可分批

参数型条目的译文写在 `locales.<lang>`；补充字段（`dimensions`、`interface` 等）缺失时回落源语言，不报错也不告警。**整块缺译**或 `REQUIRED_TRANSLATION` 必填字段缺失都会让 `npm run validate` 判错并中止构建；具体字段清单以 `scripts/validate-content.mjs` 的 `REQUIRED_TRANSLATION` 为准，不在文档里复制。

正文型集合（指南、问答）按目录分语言：`foo.md` 与 `zh/foo.md` 一一配对，缺文件即构建失败。同一 slug 每种语言只能有一个文件；缺译时不生成该语言页面，不拿源语言正文凑页面。

### 5.4 页面怎么拿到正确语言的数据

不要在模板里写 `locale === 'zh' ? ... : ...`。参数型集合统一用视图函数（`categoryView` / `modelView` / `applicationView` / `caseView`），它们按字段回落源语言；`guides` / `faqs` 条目本身就是该语言的完整内容，直接读 `entry.data`。实现见 `src/lib/content/localize.ts`。

### 5.5 hreflang 与 canonical

页面只传 **语言无关路径**，其余由布局推导：

```astro
<BaseLayout locale="zh" path={`/products/${id}/`} ...>
```

布局自动算出：canonical `/zh/products/...`、三条 hreflang（`en` / `zh-CN` / `x-default`）、`<html lang="zh-CN">`、`og:locale`（按 `LOCALE_META`）。

`noindex` 页面（如 404）**不输出 canonical、`og:url` 与 hreflang**：`BaseLayout` 在 `noindex` 时清空 alternates；`SEO.astro` 对 canonical/og:url 做条件判断。

### 5.6 加一种新语言要动哪些地方

入口是 `src/i18n/routing.ts` 的 `LOCALES`，再补 `LOCALE_PREFIX` / `LOCALE_LABELS` / `LOCALE_META`、`ui.ts` 的 `Dict`、各集合译文、页面条目的 `seo`、`organization.ts`（按需）与 `_headers` / `_redirects` 的分语言 404 规则。

分发器、`[lang]/404.astro`、`build-guard.mjs` 与 sitemap 都按 `LOCALES` 自动跟随，不需要改。

完整步骤（含 `tests/` 语言断言与 `Footer.astro` 的语言分支）见 `.codebuddy/skills/add-locale/SKILL.md`；本节只做索引，不复制清单。

## 7. 加内容：新增一个型号

1. 在 `src/content/models/` 下新建 `<型号slug>.json`，文件名必须等于 `toSlug(code)` 的结果（如 `A1` → `a1.json`、`SX_200` → `sx-200.json`）。文件名同时决定型号 URL：`/products/<slug>/`；不得与任何品类 id 相同。
2. 结构照 `src/content/models/a1.json`：`code`、`name`、`category`、`status`、`keyParams`（恰好 5 项）、`specGroups`、`seoTitle`、`seoDescription`；字段全集以 `src/content.config.ts` 为准。
3. 补 `locales.zh` 必填字段；具体清单以 `REQUIRED_TRANSLATION` 为准。
4. 跑 `npm run validate` 与 `npm run test`；页面自动出现，不需要注册路由。

三个容易踩的点：

1. `keyParams` 必须恰好 5 项。
2. `keyParams` 键名必须与品类的 `comparisonParams` 同语言对齐；不匹配时对应单元格渲染 `—`，构建不报错。
3. `seoTitle` / `seoDescription` 自己写，程序只补后缀、只校验长度；规则见 `seo-copy`。

完整步骤与模板见 `.codebuddy/skills/content-model/SKILL.md`。

## 8. 加页面：新增一个栏目

页面文案按「一个页面一个文件」组织，新增一个两段式栏目只需要两步：

1. **新建条目**：`src/data/pages/entries/<栏目>.ts`，写 `path`、`seo`（双语必填）、`content`（标题/定位段/当前状态），
   要进导航就加 `nav` 字段（`main` 为主导航、`footer` 为页脚某栏，`order` 决定顺序）
2. **登记两行**：`src/data/pages/index.ts` 里加一行 import 与 `PAGES` 中一项（同一个文件，永远是追加）

路由（含 `/zh` 版本）、页脚入口、SEO 宽度与唯一性校验、sitemap 收录都自动生效，
`render.ts`、分发器、`navigation.ts` 与 `Header/Footer` 一行都不用改。
若栏目要展示某个集合的列表，还需在 `src/lib/pages/static.ts` 的 `sectionContent()` 里按 `path`
加一个分支；未登记时页面照常生成，只是列表为空（由 `SectionBody` 渲染空状态）。

新增场景：
- 一条内容（型号 / 文章 / 案例）→ 对应 `content-*` 技能。
- 一个两段式栏目页 → `page-entry`。
- 一种新版式 → `layout-body`。
- 全站/产品线视觉改版（全宽、德系极简、扁平型号目录）→ `industrial-design`。

详情路由（`/applications/[id]/`、`/case-studies/[id]/`、`/resources/guides/[slug]/`、`/resources/faq/[slug]/`）
已在分发器内统一实现：录入对应集合的内容即自动产出页面，不需要手写 `getStaticPaths`。

## 9. 四道校验关

| 关 | 时机 | 管什么 | 失败表现 |
|---|---|---|---|
| 类型检查 | `npm run check`（已并入 build） | props 缺失、类型不匹配 | 列出文件与行号 |
| 单测 | `npm run test` | Vitest 单测（清单见 `tests/`） | Vitest 列出失败用例 |
| 内容体检 | `astro:build:start` | 标题/描述宽度与唯一性、重复填充与占位词、引用完整性、编码与文件名一致、缺译判错、中英文对比列覆盖、Markdown 语言配对、页面路径与导航顺序合法性、图片路径与 `<img>` 必填属性 | `[校验] 未通过：N 项错误` |
| 链接检查 | `astro:build:done` | 站内链接落点，以及各语言页面是否一一配对 | `[链接检查] 发现 N 条断链 / 缺少语言版本` |
| 旧路径 301 | `astro:build:done` | 把型号旧路径 `/products/<品类>/<型号>/` 写入 `dist/_redirects`（含 `/zh` 与不带斜杠形式） | 规则冲突时中断 |
| 301 实跳 | `node scripts/check-redirects.mjs --base <url>`（构建后） | 规则完整性 + 旧 URL 301 → 200 → canonical 扁平 | 退出码 1 |

`npm run test` 使用 `vitest.config.ts` 固定的 `vmForks` 池；原因见该文件注释。

**长度按显示宽度算，不是字符数。** 中文按 2、英文按 1，阈值统一是 `SEO_LIMITS` 的标题 50–60 / 描述 140–158；标题量的是**补完品牌后缀后**的宽度。

这也是为什么中文标题写起来比英文短——不是规则不同，是同一把尺子。

## 10. 排查常见问题

### 构建报 `Node.js vX is not supported by Astro`

Node 版本不对，不是代码问题。`nvm use` 后再来。

### 构建报 `[seo] … 标题宽度 N，应在 <SEO_LIMITS 区间>：<标题>`

标题太短或太长（宽度按**补完品牌后缀后**计算）。补一项真实参数（量程、精度、防护等级、认证），**不要加虚词凑字数**；具体区间读 `src/data/site.ts` 的 `SEO_LIMITS`。

### 构建报 `品类 category-a：对比表列 IP Rating 在 keyParams 中缺少同名键`

型号的参数键名和品类的对比列对不上。两边改成同一个词。

### 构建报 `[链接检查] 站内链接目标不存在：/xxx/`

页面上链到了一个没建的页面。若是计划内的页面，把它加进 `check-links.mjs` 的 `PENDING_ROUTES`（语言无关路径，`/zh/xxx/` 会被自动归一）；若是拼错了，修链接。

### 构建输出 `没有已发布内容。Astro 构建时会提示该集合不存在，属预期状态`

脚本只对 `validate-content.mjs` §5 列出的集合查空，且按**已发布**条目数判断。集合被清空或全部标为 `draft` 时告警，不阻断构建。

### 构建报「缺少中文译文：该语言页面会整片显示源语言内容」

该参数型条目（品类/型号/应用/案例）没有 `locales.zh`，或其中缺少必填字段。补译文即可；如果不打算发布中文版这个页面，
应该先不录入，而不是带着英文正文上线。

### 构建报「缺少中文版本，应新建 src/content/guides/zh/xxx.md」

指南/问答按目录分语言，这个 slug 只有英文文件。照着报错里的路径建中文文件并写完正文即可。
校验同时会拦「同一 slug 在同一语言下出现两个文件」和「正文为空」——这两种都会让页面互相覆盖或变成空壳。

### 构建末尾打印 `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c`

Node 24 在 Windows 上的已知 libuv 退出噪音（异步句柄关闭竞态），出现在 `astro:build:done` 钩子收尾阶段，**间歇性出现**。
判定标准：只要退出码为 0、`链接检查通过` 与 `Complete!` 都已打印，产物就是完整的，可忽略；Linux CI 不受影响（该断言在 Windows 专属代码路径）。
退出码非 0 或守卫日志缺失才是真失败，按对应条目排查。

### 页面里个别字段是英文

`dimensions`、`interface` 这类补充字段没翻时按字段回落源语言，**不报错也不告警**（`REQUIRED_TRANSLATION` 不检查它们）。
要消除就补齐；确认无需翻译的可以直接保留。

### 改了 `content/*.json` 但页面没变

`npm run dev` 会热更新；如果还不变，看终端有没有 schema 校验报错——不合规的数据不会进页面。

### `npm run build` 卡住或提示缺 `@astrojs/check`

`astro check` 依赖已装。若被删，`npm i -D @astrojs/check typescript`。

## 页面分工（防止关键词蚕食）

首页、产品总览、品类页、型号页各自守自己的词，**不要让两层去抢同一个词**：

| 页面 | 负责的词 | 不许做的事 |
|---|---|---|
| 首页 `/` | 品牌 + 采购大类词（OEM / 经销商 / 供应商） | title 里写 `catalogue` / `model range` / 「全部产品」「产品总览」——那是总览页的词 |
| 产品总览 `/products/` | catalogue / model range / 全品类 + 型号长尾入口 | 把某个品类的对比表或整段品类正文搬来——品类词仍由品类页主攻 |
| 品类页 | 具体品类词（压力变送器、流量计…）——**主力页** | 内容单薄：品类词要排上去靠这里的正文、参数对比表与内链 |
| 型号页 | 型号长尾词 | — |

**两条硬边界**：

- **首页品类简介保持 80 字截断**；总览页不再放品类摘要，而是型号目录——两页不要重复同一批品类文案。
- **首页 title 不出现"目录 / 总览"类词**——首页是品牌与入口页，`catalogue` 归 `/products/`。

两页的 `canonical` 各自指向自身、ItemList 结构化数据语义不同（首页 = 精选型号，总览 = 全部型号；数量由集合决定），这两点已由框架保证，无需每次检查。

## 页面结构统一规范（新增页面前对照）

所有内页共用同一骨架：`PageHeader`（白底 + 1px 下边线，**放在 `.section` 之外**，内部自带 container，
`width: 'wide' | 'narrow'`）→ `<section class="section"><div class="container">` 正文板块 →
页尾 `CtaBand`（石墨 full-bleed，内部自带 container）。PageHeader 是全站唯一 h1。

- **标题层级**：h1（PageHeader 唯一）→ h2（`SectionTitle`：细线 + 可选右侧链接）→ h3（分组/卡片），不跳级
- **间距节奏**：`.section`（clamp 56–112px）与板块间距用 `--space-*`；具体值见 `tokens.css`
- **断点**：480 / 768 / 1024 / 1280 / 1440；header 在 1024 折叠；卡片/规格网格优先 `auto-fit|auto-fill minmax(min(100%, Npx), 1fr)`，不新增断点
- **按钮**：只用全局 `.btn` + 变体（`--primary/--secondary/--ghost/--on-dark`），每个视口区域只一个填充主按钮；不写局部按钮样式
- **编辑型页面**（关于 / 栏目页 / 询价）：桌面双栏 grid，侧栏卡片 sticky 于 `top: calc(var(--header-h) + 16px)`
- **空集合页面**必须给「状态说明 + 至少 3 条替代入口」，不留空白页与死路
- **只取 tokens**：颜色 / 字号 / 间距一律用 `--color-*`、`--fs-*`、`--space-*`，组件内不写死色值（深色带上的白色例外）
- **表格**：对比/规格表外层套 `.table-scroll`（`tabindex="0"` + `role="region"` + `aria-label`），只在表内横滚
- **图片**：规格见 `docs/开发框架设计.md` §7.5；必写 `width`/`height`，`alt` 有语义
- **SEO**：每页唯一 title / description；面包屑 + `BreadcrumbList`；页面至少 2 条站内链

验收：`astro check` 0 错误、`vitest` 全绿、`validate` 通过、390 / 768 / 1024 / 1440 无横向溢出、每页 h1 唯一且内链 ≥2。

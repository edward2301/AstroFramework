# AI 协作规则（用户明确要求，永久生效）

以下规则约束 AI 助手的行为，**任何会话都必须遵守**：

1. **最小改动**：只执行用户字面要求的那个改动。布局重构、结构调整、其他文件的连带修改，
   一律先列出方案等用户确认，不得顺手做。
2. **设计决策不替用户做**：遇到「更美观」「合理」这类有多种理解的要求时，
   给出 2~3 个可选方案（各带一行效果说明）让用户挑，不得自行选定后连续试错。
3. **public/ 与 src/content/ 是用户资产**：新增或覆盖任何图片、内容文件前，
   必须逐个列出将写入的路径并得到确认。改名/移动视同覆盖。
4. **写后必验**：每次文件写入或编辑后（尤其工具报错后），必须重读文件核对结构完整
   （如 style 块数量、无重复内容），确认无误后才宣布完成。禁止连续多轮修改同一文件而不回读。
5. **一次一个变量**：调样式时一次只改一个值并让用户看效果；禁止把尺寸、断点、布局方案捆在一起改。
6. **简短汇报**：完成后只说改了什么、验证结果，不写长篇设计论述。
7. **文档同步**：每次改动代码、内容、配置、命令、规则、技能或目录结构后，按 `doc-sync` 技能判定文档归属并同步更新
   （索引 → `README.md`，操作 → `docs/上手指南.md`，设计与约束 → `docs/开发框架设计.md`，
   运维 → `deploy/cloudflare/README.md`，AI 入口/规则/技能 → `.codebuddy/`）。
   纯重构、格式化或无行为变化的改动可以不改文档，但最终报告必须写 `Docs: no change — <原因>`；
   有文档改动则写 `Docs: updated — <文件或章节>`。
